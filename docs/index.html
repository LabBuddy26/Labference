Build, collect and evaluate with LabBench.

A practical guide for running the benchmark, collecting demonstrations and connecting an external policy service to Isaac Sim.

01 / Overview

One benchmark vocabulary

LabBench evaluates embodied agents on chemistry laboratory manipulation. Long-horizon L tasks measure ordered multi-stage procedures; reasoning-in-action R tasks measure decisions grounded in visual or structured laboratory state. Each task uses a reproducible YAML configuration and an explicit success predicate.

02 / Setup

Download the repository and prepare Isaac Sim

Clone the repository, activate the Isaac Sim Python environment and verify the core imports before launching a task.

git clone https://github.com/<user>/<repo>.git
cd LabBench
conda activate env_isaaclab
python -c "from isaacsim import SimulationApp; print('Isaac Sim OK')"
python -c "import hydra, omegaconf, yaml, h5py; print('Dependencies OK')"

Keep the repository assets available locally. Large USD meshes and textures may be distributed separately from the Git repository.

03 / Collection

Collect synchronized robot demonstrations

The simulator advances at 60 Hz. The default collector records synchronized samples at 10 Hz, one sample every six physics steps. Use an explicit task configuration from config/.

python main.py \
  --config-dir config \
  --config-name level1_pick \
  --mode collect \
  --backend numpy \
  --headless

Override the sampling rate only when required:

python main.py --config-name level1_pick --mode collect --sample-hz 60

For batch collection, use the task list and set the desired number of successful episodes:

python -m utils.collect_driver start \
  --task-list collection_tasks.txt \
  --workers 1 \
  --gpu-ids 0 \
  --success-episodes 200 \
  --headless \
  --no-video

04 / Training interface

Train against the LabBench action contract

Use the synchronized front and wrist RGB observations together with robot state. The default action representation is actions_ee: seven end-effector pose values followed by one binary gripper command.

Observationscamera_1_rgb + camera_3_rgb
Robot stateFranka arm joints and gripper state
ActionEE pose 7 + binary gripper 1
Gripper0 = close · 1 = open
Timing10 Hz policy samples over 60 Hz physics

OpenPI and GR00T training commands are maintained by their respective external repositories. Configure those projects to read the LabBench observation names and emit the contract above.

05 / Independent release protocols

New tasks, separate denominators

The release suite contains centrifuge opposite-slot (easy/hard), feedback weighing (easy/hard), and rack placement recall (easy, same-cap hard and distinct-cap hard). The reference controller is used for collection and scene validation; only declared external policies with ranking_eligible=true enter the independent model board.

Protocol suitelabference_release_protocols_v1
Dataset fieldsactions + actions_ee + action_gripper
Camera namescamera_1_rgb + camera_3_rgb
Extra weighing viewsdisplay_rgb + weights_rgb
Rates10/60 Hz or 20/120 Hz per protocol
Outputvalidity, completion and task-owned diagnostics

Open the task catalogue for protocol contracts or the independent board for model results.

06 / Policy service

Connect an external policy

Start the OpenPI or GR00T inference service separately, then set the matching provider, host, port and protocol in the task YAML under evaluation.policy. The evaluator validates camera fields, state keys, action dimensions and finite numeric values before execution.

evaluation:
  policy:
    provider: gr00t
    profile: eai4s_eval/configs/policies/gr00t_franka_ee_pos_v1.yaml
    host: 127.0.0.1
    port: 5555
    protocol: zmq

GR00T must return action.single_arm[T,7] and action.gripper[T,1]. The evaluator maps the binary gripper value to the physical Franka finger target.

07 / Simulation evaluation

Run a reproducible task evaluation

Evaluation uses the same scene and camera configuration as collection, while the policy controls the task at 10 Hz and the simulator continues at 60 Hz. Choose a split and an episode budget explicitly.

python main.py \
  --config-dir config \
  --config-name level1_pick \
  --mode eval \
  --backend numpy \
  --headless

For direct TaskSpec evaluation, use the benchmark CLI:

python -m eai4s_eval.cli.run_benchmark_eval \
  --benchmark-root /path/to/LabBench \
  --task-spec eai4s_eval/configs/tasks/B01_level1_pick.yaml \
  --policy-profile eai4s_eval/configs/policies/gr00t_franka_ee_pos_v1.yaml \
  --vla-host 127.0.0.1 --vla-port 5555 \
  --policy-provider gr00t --policy-backend zmq \
  --split sim_dev --num-episodes 5 \
  --backend numpy --headless

sim_clean is the nominal split, sim_dev samples within configured ranges and sim_randomized is the robustness split. All 24 L/R tasks are implemented and included in the official suite.

08 / Troubleshooting

Common launch and evaluation issues

Hydra cannot find a configRun from the repository root and pass --config-dir config.
Isaac Sim import failsActivate the Isaac Sim environment before launching main.py.
Camera contract errorUse camera_1_rgb and camera_3_rgb; camera2 is not part of the default contract.
Policy connection errorStart the service first and match host, port and protocol in the YAML.
Action shape errorReturn a horizon of 7-D arm pose values plus a 1-D binary gripper value.
Immediate task failureRead the printed failure reason and verify scene stability, target reachability and the selected task configuration.
